# AI 知识管理设计

修改日期：2026-11-26。

## 首版边界

知识库为主体，新增能力默认关闭。仅后台 JWT 用户可以使用管理助手；拒绝 API token 和前台访客身份进入写入接口。当前知识库为工具作用域，不支持跨库写入。关闭、手动保存、自动草稿三个模式均由人工发布。高风险、冲突与合并不会自动应用，首版不向模型开放删除、发布、权限或任意代码工具。

## 复用与调用

后台助手调用原 ChatUsecase、ModelKit、RAG、conversation_messages 和流式输出。消息气泡从原前台问答组件抽到共享 UI，两端复用；管理端沿用既有 SSEClient、Markdown 与 Tiptap 编辑器。受控 JSON 协议兼容不支持原生 Function Calling 的模型，最多八次工具调用。

工具提供当前知识库信息、目录/文档列表、语义与标题检索、完整文档读取以及 propose_change。创建、补充、修改均以 CREATE/APPEND/UPDATE 候选形式实现；模型不能直接发布。propose_change 先登记本轮意图，聊天成功持久化后才提交整理任务。

## 提取与审核

聊天成功完成后只登记持久任务。累计三轮或闲置五分钟后处理，显式整理立即调度。PostgreSQL 保存任务、来源消息范围和水位，NATS 只携带任务 ID，cron 每分钟恢复未投递记录和过期租约。每次提取最多两次结构化模型调用：价值判断，然后结合真实相似文档和待审核知识决定忽略、新建、补充、更新或冲突。

服务端校验来源消息、目标库/文档/导航/目录、用户身份、策略和正文敏感信息。至少包含一条用户消息，AI 的确认声明不能赋予发布权限。内容只在收件箱保存，审核编辑复用现有编辑器。HTML 自动补充或无法安全局部替换时保持原文并标记高风险，要求人工编辑。

批准事务锁定建议与目标节点，检查节点 revision、原文及目录一致，再调用原 NodeUsecase 与发布逻辑。发布、建议状态、审计和索引 outbox 同事务提交；向量消费者保留原有幂等和旧索引清理。发布与索引学习状态分开呈现。

## 权限、恢复与限制

用户/目录策略取权限交集。folder_ids 中空字符串表示根目录，* 表示管理员显式授权全部目录。任务运行和审核时重新校验权限；READONLY 也限制后台任务。任务租约带 fencing token，取消或过期执行不能提交；后台聊天幂等键使用同一持久任务表作为请求凭据，重复请求返回 409。默认全局两个任务并发，三次尝试，每次模型调用最多120秒，每库每日50次新增模型调用，预算不足暂停。

后台会话有 admin_user_id 和独立授权水位。原会话读取及 nonce 接口校验所有权；审核者能看候选正文和理由，只有来源会话所有者可以展开原聊天。删除聊天后来源 ID 留作审计，原聊天读取返回不存在，不复制聊天全文进公开文档。

回滚生成高风险反向建议，仍需审核和版本校验。新建文档的回滚不执行删除。重新提取复用冻结消息范围且不倒退水位。

模型输出、网页和文档均为不可信输入，权限边界由后端执行。敏感检测为保守规则而非完整 DLP；不应输入受限制业务数据，人工审核仍需确认共享适当性。独立 RAG 和模型服务的真实效果与离线能力必须另行验收。
