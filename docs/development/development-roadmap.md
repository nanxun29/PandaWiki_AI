# 开发路线

## 本轮：两个 P0

1. 建立固定源码基线、架构分析与真实构建记录。
2. 后台授权助手复用原聊天服务，提供读取及知识建议工具。
3. 收件箱、差异审核、人工发布、事务 outbox、索引状态及并发保护。
4. 增量自动提取、持久任务、目录推荐、去重、策略和来源权限。
5. PostgreSQL/NATS 集成测试、社区版构建与中文运维文档。

并发保护、敏感信息、审计和反向建议随 P0 前置，不因列为 P1 而省略基础安全。

## 后续 P1

增加段落级精细 diff、更多敏感信息识别与配置、复杂 HTML 增量策略、独立审核角色、细粒度发布风险规则。开放低风险自动发布前必须提供额外的可重复验收数据和显式授权。

## 后续 P2

授权任务身份下的周期维护、过期/冲突/重复检查和维护报告，随后评估 MCP 与外部 Agent。继续复用原检索和发布系统，不引入知识图谱、多智能体或新向量数据库。

## 上游维护

保留 upstream 与原 Go module path，避免品牌修改造成导入路径重构。按功能提交，记录对聊天/发布/认证接缝的修改；同步上游时重点回归迁移序号、Wire、SSE 和正文格式。不得自动推送上游、合并或发布正式版本。
